---

Stackkit uses two JSON files to manage your project. Understanding the role of each prevents confusion when inspecting or evolving a generated project.

**`stackkit.config.json`** is the file you author. It describes the desired stack — which modules to include, which package manager to use, and any per-module options. Stackkit reads this file when you run `init`, `generate`, or `migrate`.

**`.stackkit/project.json`** is the manifest Stackkit writes and owns. It records exactly what was generated so commands like `info`, `doctor`, `diff`, and `migrate` can inspect and evolve the project over time. You should not hand-edit this file; keep it in sync by running Stackkit commands.

<Callout title="Config vs. manifest" type="info">
`stackkit.config.json` is your **input** — edit it freely to change your desired stack.
`.stackkit/project.json` is **generated state** Stackkit owns — it is rewritten by Stackkit commands and should not be edited by hand.
Run `stackkit doctor` to validate that the manifest exists, is structurally valid, and matches the on-disk state of managed files.
</Callout>

## `.stackkit/project.json`

The project manifest is generated by Stackkit and stored at `.stackkit/project.json` relative to your project root. It is the authoritative record of what Stackkit has built and how.

### `schemaVersion`

Always `1`. Used internally to detect format changes between Stackkit releases.

```json title=".stackkit/project.json"
{
  "schemaVersion": 1
}
```

### `stackkitVersion`

The version of Stackkit that generated or last updated this manifest. Stackkit uses this to determine whether a migration is needed before running commands against an older project.

```json title=".stackkit/project.json"
{
  "stackkitVersion": "1.2.0"
}
```

### `projectName`

The project slug. Matches the `projectName` from `stackkit.config.json` at generation time.

```json title=".stackkit/project.json"
{
  "projectName": "my-app"
}
```

### `packageManager`

The package manager used when the project was generated. One of `pnpm` (default), `npm`, `yarn`, or `bun`.

```json title=".stackkit/project.json"
{
  "packageManager": "pnpm"
}
```

### `source`

Describes how the project was created. The object is discriminated by a `kind` field.

| `kind` | When used |
| --- | --- |
| `"config"` | Default — project was generated from a `stackkit.config.json` file. |
| `"scripted"` | Project was created via a programmatic API. |
| `"recipe"` | Project was created from a shareable recipe code. |
| `"interactive"` | Project was scaffolded through the interactive CLI prompts. |

```json title=".stackkit/project.json"
{
  "source": { "kind": "config", "path": "stackkit.config.json" }
}
```

```json title=".stackkit/project.json (recipe)"
{
  "source": { "kind": "recipe", "code": "sk_abc123" }
}
```

### `paths`

A map of named paths used internally by Stackkit modules. Defaults to `{ "root": "." }`.

```json title=".stackkit/project.json"
{
  "paths": {
    "root": "."
  }
}
```

### `createdAt`

ISO 8601 timestamp recording when the project was first generated.

```json title=".stackkit/project.json"
{
  "createdAt": "2025-03-14T10:00:00.000Z"
}
```

### `modules`

Array of the modules Stackkit generated into the project. Each entry records the module ID, the version that was installed, and any resolved options.

```json title=".stackkit/project.json"
{
  "modules": [
    {
      "id": "eslint",
      "version": "2.1.0",
      "options": {}
    },
    {
      "id": "typescript",
      "version": "1.4.2",
      "options": { "strict": true }
    }
  ]
}
```

### `files`

Array of managed files that Stackkit owns. Each entry stores the file path, the module that owns it, and a content hash. These records power `stackkit diff` (surface drift from what Stackkit wrote) and `stackkit doctor` (detect missing or modified managed files).

```json title=".stackkit/project.json"
{
  "files": [
    {
      "path": "eslint.config.js",
      "owner": "eslint",
      "hash": "sha256-e3b0c44298fc1c149afb"
    },
    {
      "path": "tsconfig.json",
      "owner": "typescript",
      "hash": "sha256-a87ff679a2f3e71d9181"
    }
  ]
}
```

### `aiSkills`

AI skill configuration state. Records how skills are installed, which agents are targeted, and the current state of installed, planned, local, and unresolved skills.

The `targets` array maps each agent identifier (e.g. `codex` → `.agents`, `claude` → `.claude`) to the directory where skills are placed.

```json title=".stackkit/project.json"
{
  "aiSkills": {
    "mode": "install",
    "linkMode": "copy",
    "targets": [
      {
        "agent": "codex",
        "directory": ".agents",
        "enabled": true
      }
    ],
    "installed": [],
    "planned": [],
    "local": [],
    "unresolved": []
  }
}
```

### `migrations`

Records which managed-update migrations Stackkit has applied to this project. Used by `stackkit migrate` to determine which migrations are outstanding.

```json title=".stackkit/project.json"
{
  "migrations": {
    "applied": []
  }
}
```

### Full example

```json title=".stackkit/project.json"
{
  "schemaVersion": 1,
  "stackkitVersion": "1.2.0",
  "projectName": "my-app",
  "packageManager": "pnpm",
  "source": { "kind": "config", "path": "stackkit.config.json" },
  "paths": { "root": "." },
  "createdAt": "2025-03-14T10:00:00.000Z",
  "modules": [
    { "id": "eslint", "version": "2.1.0", "options": {} },
    { "id": "typescript", "version": "1.4.2", "options": { "strict": true } }
  ],
  "files": [
    { "path": "eslint.config.js", "owner": "eslint", "hash": "sha256-e3b0c44298fc1c149afb" },
    { "path": "tsconfig.json", "owner": "typescript", "hash": "sha256-a87ff679a2f3e71d9181" }
  ],
  "aiSkills": {
    "mode": "install",
    "linkMode": "copy",
    "targets": [
      { "agent": "codex", "directory": ".agents", "enabled": true }
    ],
    "installed": [],
    "planned": [],
    "local": [],
    "unresolved": []
  },
  "migrations": { "applied": [] }
}
```

## `stackkit.config.json`

This is the file you create and maintain. Place it in your project root. Stackkit reads it during `init`, `generate`, and `migrate`.

### `projectName`

The project slug. Used as the default directory name and recorded in the manifest.

### `preset`

Optional preset name. When specified, Stackkit applies a predefined set of modules and options before merging your explicit config.

### `packageManager`

The package manager to use. One of `pnpm` (default), `npm`, `yarn`, or `bun`.

### `workspace`

Specifies the workspace strategy. Currently `"pnpm-turbo"` is supported, which sets up a pnpm workspace with Turborepo.

### `modules`

Array of module IDs to include. Stackkit installs and generates each listed module.

### `registries`

A map of registry name to URL. Defaults to `{}`. Use this to point Stackkit at private or custom module registries.

### `options`

Optional per-module options. A map of module ID to an options object. Options here are merged with any defaults the module declares.

### `ai`

AI skill configuration. Controls how Stackkit installs AI skills into the project.

| Field | Default | Description |
| --- | --- | --- |
| `skillTargets` | `["codex"]` | Which agent targets to install skills for. |
| `skillMode` | `"install"` | How skills are managed (`install` adds skills to the target). |
| `linkMode` | `"copy"` | How skill files are placed (`copy` writes a file copy to the target directory). |

### Full example

```json title="stackkit.config.json"
{
  "projectName": "my-app",
  "preset": "fullstack",
  "packageManager": "pnpm",
  "workspace": "pnpm-turbo",
  "modules": ["eslint", "typescript", "prettier"],
  "registries": {},
  "options": {
    "typescript": { "strict": true }
  },
  "ai": {
    "skillTargets": ["codex"],
    "skillMode": "install",
    "linkMode": "copy"
  }
}
```

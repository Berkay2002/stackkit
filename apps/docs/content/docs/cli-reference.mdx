## Command Summary

| Command | Description |
|---|---|
| `stackkit create` | Generate a new managed monorepo |
| `stackkit info` | Show the current project state from `.stackkit/project.json` |
| `stackkit doctor` | Check managed files for drift against canonical templates |
| `stackkit diff --file <path>` | Diff a specific managed file against its template |
| `stackkit preset list` | List all available presets |
| `stackkit preset inspect <id>` | Show the modules and flags a preset resolves to |
| `stackkit recipe encode` | Encode a preset or stack as a portable offline recipe code |
| `stackkit recipe inspect <code>` | Decode and inspect a recipe code |
| `stackkit module list` | List all available modules |
| `stackkit module search <query>` | Search modules by name or keyword |
| `stackkit module inspect <id>` | Show a module's full declaration |
| `stackkit registry list` | List locally registered module sources |
| `stackkit add` | Add a module to an existing managed project *(alpha)* |
| `stackkit remove` | Remove a module from a managed project *(alpha)* |
| `stackkit update` | Update generated files for existing modules *(alpha)* |
| `stackkit migrate` | Run versioned migrations for managed modules *(alpha)* |
| `stackkit skills sync` | Sync AI skill targets for the current stack *(alpha)* |
| `stackkit skills update` | Update AI skill content in the project *(alpha)* |

## Create

Generate a new managed monorepo using stack-axis flags.

```bash
stackkit create <project-name> [flags]
```

**Stack-axis flags**

| Flag | Description |
|---|---|
| `--web <framework>` | Web app framework (e.g. `next`, `vite`, `tanstack`) |
| `--ui <shadcn\|tailwind\|none>` | UI layer; defaults to ShadCN for React frameworks; `none` to opt out, `tailwind` to swap |
| `--api <framework>` | API framework (e.g. `fastapi`) |
| `--db <database>` | Database module (e.g. `postgres`) |
| `--db-provider <host>` | Postgres host/provider: `neon`, `supabase`, `supabase-local`, `postgres-local` (omit for bring-your-own `DATABASE_URL`) |
| `--db-runtime <mode>` | Database client runtime: `node` (default) or `edge`. `edge` applies to Neon + Drizzle and emits the `@neondatabase/serverless` client |
| `--auth <provider>` | Auth provider (e.g. `auth0`) |
| `--with <modules>` | Comma-separated additional modules (e.g. `shadcn,docker`) |
| `--deploy <target>` | Deployment target (e.g. `vercel`) |
| `--ts-quality <eslint-prettier\|biome>` | TypeScript lint + format toolchain (default `eslint-prettier`; `biome` replaces ESLint + Prettier) |
| `--py-typecheck <mypy\|pyright>` | Python type checker (default `mypy`) |
| `--preset <id>` | Use a named preset instead of individual flags |
| `--recipe <code>` | Use an offline recipe code |
| `--skills skip` | Skip AI skill installation |
| `--yes` | Accept all prompts automatically |

**Example**

```bash
stackkit create my-app \
  --web next \
  --api fastapi \
  --db postgres \
  --auth auth0 \
  --with shadcn,docker \
  --deploy vercel
```

**Web framework examples**

```bash
# React SPA with Vite.
stackkit create my-spa --web vite

# Full-stack React with TanStack Start.
stackkit create my-app --web tanstack

# Swap ShadCN for plain Tailwind, or opt out of a UI layer entirely.
stackkit create my-app --web vite --ui tailwind
stackkit create my-app --web vite --ui none
```

The `--ui` flag tunes the UI layer for the stack-axis flags above. It does not apply to `--recipe` or `--config`, which carry their own complete module list.

**Tooling slots**

Stackkit models developer tooling as per-language Tooling Slots — `lint`, `format`, and `typecheck` — filled by Quality Modules. Every language present in the stack gap-fills its default tools, so you only need a flag to choose an alternative.

| Language | Lint | Format | Typecheck |
|---|---|---|---|
| TypeScript | ESLint | Prettier | tsc |
| Python | Ruff | Ruff | mypy |
| Rust | Clippy | rustfmt | cargo check |

`--ts-quality biome` swaps Biome in as a combined linter and formatter, replacing ESLint and Prettier (the `typecheck` slot stays on tsc). `--py-typecheck pyright` swaps Pyright in for mypy in the Python `typecheck` slot. Choosing an alternative suppresses the default it covers rather than conflicting with it.

```bash
# Use Biome instead of ESLint + Prettier.
stackkit create my-app --web next --ts-quality biome

# Use Pyright instead of mypy for a FastAPI service.
stackkit create my-app --api fastapi --py-typecheck pyright
```

Rust tooling (Clippy, rustfmt, cargo check) is modeled in the registry, but its config files are not yet generated.

**Postgres host examples**

```bash
# Cloud Supabase as the Postgres host (no Docker). Emits a DIRECT_URL for migrations.
stackkit create my-app --web next --db postgres --db-provider supabase

# Neon on an edge runtime — generates the @neondatabase/serverless Drizzle client.
stackkit create my-app --web next --db postgres --db-provider neon --db-runtime edge

# Local Postgres in Docker (adds docker-compose.db.yml).
stackkit create my-app --web next --db postgres --db-provider postgres-local

# Local Supabase via the Supabase CLI (adds supabase/config.toml; requires the CLI).
stackkit create my-app --web next --db postgres --db-provider supabase-local
```

## Create Without Writing Files (Dry-Run)

Preview the planned output without writing anything to disk.

**Preview a preset**

```bash
stackkit create my-app --preset next-postgres-clerk --dry-run
```

**Preview an explicit stack as JSON**

```bash
stackkit create my-app --web next --api fastapi --db postgres --auth auth0 --dry-run --json
```

**Inspect a single planned file**

```bash
stackkit create my-app --web next --dry-run --view apps/web/package.json
```

## Presets and Recipes

Presets are named collections of modules and flags. Recipes are compact, offline-shareable codes that encode a full stack configuration — they require no account and no network access.

**List available presets**

```bash
stackkit preset list
```

**Inspect a preset**

```bash
stackkit preset inspect next-fastapi-postgres-auth0
```

**Encode a preset as a recipe code**

```bash
stackkit recipe encode --preset next-fastapi-postgres-auth0
```

**Inspect a recipe code**

```bash
stackkit recipe inspect sk_...
```

**Create a project from a recipe**

```bash
stackkit create my-app --recipe sk_...
```

## Inspect and Maintain

These commands work inside an existing Stackkit-managed project.

**Show project state**

```bash
stackkit info
```

**Check managed files for drift**

```bash
stackkit doctor
```

**Diff a specific managed file**

```bash
stackkit diff --file apps/web/package.json
```

**Module discovery**

```bash
stackkit module list
stackkit module search fastapi
stackkit module inspect fastapi --json
```

**Local registry**

```bash
stackkit registry list
```
